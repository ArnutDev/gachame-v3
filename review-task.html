เสร็จสิ้นภารกิจ

บันทึกสรุปการแก้ไขข้อผิดพลาดของระบบตรวจสอบและปรับปรุง Unit Tests ให้ผ่าน 100%

ได้ทำการวิเคราะห์ แก้ไขปัญหาระบบตรวจสอบคอนฟิกแบนเนอร์ รวมถึงปรับปรุงโครงสร้าง Unit Tests ทั้งหมดในระบบตรวจวินิจฉัย (Diagnostics Dashboard) ให้ทำงานได้อย่างถูกต้องและผ่านเกณฑ์การทดสอบ 100% เรียบร้อยแล้ว รายละเอียดมีดังนี้:

1. ปัญหาการรายงานผลของ Unit Tests ที่ไม่ปกติก่อนหน้านี้

สาเหตุหลักที่ทำให้อดีต Unit Test บางตัวรายงานผลล้มเหลว (FAIL) ไม่ได้เกิดจากความผิดปกติของตัวระบบคำนวณสุ่มสถิติ (Gacha Engine) แต่เกิดจาก:

  • การสร้างโครงสร้างจำลอง (Mocking) ในแต่ละ Test Case ขัดแย้งกับกฎความปลอดภัยของแบนเนอร์: ตัวอย่างเช่น การทดสอบบังคับอัตราสุ่มเป็น 100% โดยการนำค่าเดิมไปแก้ไขเฉพาะบางส่วน ทำให้ได้อัตราความน่าจะเป็นรวมของแบนเนอร์เกินกว่า 100% (เช่น 195%, 96%, 197%) ส่งผลให้ระบบ Validator บล็อกการรันและปฏิเสธแบนเนอร์นั้นๆ ออกไป
  • ปัญหาการอ้างอิงไอเทมเด่น (Featured Items) และการสะกดข้อความ Error: มีการอ้างอิงตัวละคร Clark ที่ไม่มีอยู่ใน Mock Pool ของ Test Case รวมถึงมีข้อความยืนยันความคลาดเคลื่อนสะกดไม่ตรงกับที่ตัวเครื่องประมวลผลจริงส่งกลับมา

2. แนวทางการแก้ไข Unit Tests ในไฟล์ src/utils/engineDiagnostics.ts

  • ปรับโครงสร้าง Mock Rate ให้คำนวณได้ 100% เสมอ: แก้ไขให้แต่ละเคสทดสอบเคลียร์ค่าความน่าจะเป็นของระดับที่ไม่เกี่ยวข้องเป็น 0 และอัดฉีดเฉพาะระดับที่ต้องการทดสอบ (เช่น 8_normal: 100%) เพื่อให้ระบบ Validator อนุมัติการเข้าทดสอบอย่างสมบูรณ์
  • ปรับแต่ง Featured Items และล้างผลกระทบเก่า: ลบรายการ Featured Items และเรทสุ่มเด่นที่ค้างอยู่ใน Mock Config ของเคสทดสอบกรณี Zero-Weight หรือกรณีสุ่มพูลขนาดใหญ่ เพื่อหลีกเลี่ยงข้อขัดแย้งของอัตราสะสม
  • แก้ไขข้อความตรวจสอบข้อผิดพลาด: อัปเดตข้อความการค้นหา Error ย่อยให้ตรงกับสิ่งที่ส่งออกจาก Engine (จาก exceeds the rarity threshold limit เป็น exceeds the total rarity rate)

3. ผลการทดสอบปัจจุบัน

  • การรันชุดทดสอบ Unit Tests ทั้ง 9 ตัวรายงานสถานะเป็น PASS (ผ่านสำเร็จ) 100% ทั้งหมด
  • การคอมไพล์ในระดับ Production บิลด์สำเร็จได้อย่างสมบูรณ์
