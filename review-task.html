สรุปผลงาน Task ล่าสุด

การพัฒนาฟีเจอร์คลังสะสมประวัติการสุ่ม (On-Page Collection History)

ได้ทำการพัฒนาฟีเจอร์แสดงผลคลังสะสมของผู้เล่นในหน้าจอ Gacha (Ranger & Gear) โดยดึงข้อมูลและประมวลผลจาก Global State ร่วมกับข้อมูล JSON โดยตรง ทำให้ผู้เล่นเห็นประวัติของที่สุ่มได้อัปเดตแบบเรียลไทม์ โดยไม่ต้องเปลี่ยนหน้าเว็บไปมา:

รายละเอียดการพัฒนาล่าสุด

  • การแยกการจัดแสดงผลลัพธ์ของสะสม (Event First Display):
    • ตัวละคร/เกียร์ที่เป็นอีเวนต์ประจำเดือน: จัดให้เรียงแสดงก่อนเป็นลำดับแรกสุดในรูปแบบการ์ดสวยงาม โดยแสดงรูปภาพ (ImageContainer), ชื่อ, ระดับดาว และจำนวนที่สุ่มได้สะสม
    • ตัวละคร/เกียร์ทั่วไป (ไม่ใช่อีเวนต์): จัดเรียงแสดงผลต่อท้ายในรูปแบบแผงการ์ดข้อความขนาดกระชับ โดยแสดงเฉพาะชื่อระดับดาวและจำนวนสะสม **ไม่แสดงรูปภาพ** เพื่อความเป็นระเบียบและลดภาระอินเทอร์เน็ต
  • ระบบค้นหา (Search Component): พัฒนาคอมโพเนนต์พิมพ์ค้นหาชื่อตัวละคร/อุปกรณ์เกียร์ในคลังสะสมอัปเดตรีลไทม์
  • ระบบคัดกรอง (Inline Filter Tabs): พัฒนาชุดปุ่มคัดกรองแบบ Inline สวยงามภายในตัวเพื่อคุมพื้นที่ ได้แก่:
    • คัดกรองตามความเกี่ยวข้อง: แสดงทั้งหมด / เฉพาะของอีเวนต์ / เฉพาะของทั่วไป
    • คัดกรองตามระดับความยาก (Rarity): เลือกกรองเฉพาะระดับดาวที่สนใจ (เช่น 8★ Ultra ของ Ranger หรือ 9★ ของตู้เกียร์)
  • การประมวลผลแบบไร้การซ้ำซ้อน (Data Integrity): ทำการอ่านและดีดูพลิเคตข้อมูลรายชื่อตัวละคร (Deduplication) ข้าม Event และ Base อัตโนมัติในตอนโหลด โดยไม่มีการก๊อปปี้หรือฝังข้อมูลจำลองดิบลงในหน้า View
  • ระบบป้ายฉลากแบนเนอร์รายเดือน (Dynamic Month-Based Tags): ออกแบบระบบการอ่านประเภทตู้และเลขเดือนอย่างสมมาตรทั้ง Ranger และ Gear (โดยตัดประเภทตู้ยุบเหลือเพียง normal / boost / gear / gear_boost เท่านั้น) เพื่อจัดป้ายดังนี้:
    • เดือนคู่ (เช่น เดือน 8 Collab): ตู้ Ranger ปกติขึ้นป้าย Collab, ตู้ Ranger บัฟขึ้นป้าย Collab Rate-Up ส่วนตู้ Gear ปกติขึ้นป้าย Collab Gear, ตู้ Gear บัฟขึ้นป้าย Collab Gear Rate-Up
    • เดือนคี่: ตู้ปกติของทั้ง Ranger และ Gear จะไม่ขึ้นป้ายบอกประเภทใดๆ เลย (ไม่มี Tag) และตู้บัฟ (Boost) จะขึ้นป้ายเฉพาะคำว่า Rate-Up เท่านั้น
  • การอัปเดตระบบตรวจสอบโครงสร้างตู้สุ่ม (Banner Type Validator Update): แก้ไขไฟล์ตรวจสอบความถูกต้องโครงสร้าง JSON (Structural Validation) ให้รองรับชุดประเภทตู้ใหม่ ส่งผลให้แอปพลิเคชันทำการโหลดฐานข้อมูลเข้าระบบ (Initialization) ได้อย่างสมบูรณ์แบบไม่มีข้อผิดพลาด
  • การเรียงลำดับตู้สุ่มปกติขึ้นก่อน (Normal Banner Priority Sorting): เพิ่มคำสั่งจัดเรียงข้อมูลในระบบ View ให้ตู้สุ่มรูปแบบปกติ (Normal / Gear) อยู่ลำดับแรกสุดในรายการแบนเนอร์เสมอ ตามด้วยตู้บัฟเรตอัป (Rate-Up) เพื่อให้ผู้เล่นเลือกตู้สุ่มได้ง่ายเป็นระบบครับ
ตัวอย่างเปรียบเทียบในชีวิตประจำวัน: "การจัดการอัลบั้มสติกเกอร์สะสมของเล่นหลังจากหมุนกาชาปอง"
* การจัดวางแสดงผลการ์ดแบบแยกรูป/ข้อความ: เปรียบเหมือนเวลาที่เรานำของเล่นที่สุ่มได้มาจัดเรียงในตู้โชว์ โดยเลือกหยิบตุ๊กตาตัวลิมิเต็ดอีเวนต์ที่หายาก [Event Rangers] มาตั้งเรียงแถวหน้าสุดพร้อมกล่องรูปภาพโชว์ความสวยงาม ส่วนตุ๊กตาหมีตัวธรรมดาทั่วไป [Base Rangers] ที่มีอยู่เยอะมากและไม่เด่น เราก็นำไปจดบันทึกเป็นรายชื่อสรุปแปะกระดาษไว้ท้ายตู้โชว์เฉยๆ เพื่อประหยัดพื้นที่ในการจัดแสดงแต่ยังสามารถตรวจสอบนับจำนวนได้
* ช่องค้นหาและตัวกรอง: เปรียบเหมือนการเปิดสมุดสารบัญเช็กรายชื่อของเล่นเพื่อค้นหาอย่างรวดเร็วโดยไม่ต้องหยิบกวาดดูทีละตัว
