01

Script Refactoring

ยกระดับไฟล์สคริปต์หลัก update.py ให้มีประสิทธิภาพและเป็นระบบอัตโนมัติมากยิ่งขึ้น

  • Dynamic Pathing: ทำงานผ่าน Path สัมพัทธ์ทั้งหมด ไม่ขึ้นตรงกับโฟลเดอร์เครื่องเดิม
  • Built-in Selenium Manager: เลิกใช้ไลบรารีดึง Driver ภายนอกเพื่อขจัดข้อผิดพลาดทางสถาปัตยกรรม
  • Console UTF-8: บังคับส่งสัญญาณออกเป็น UTF-8 เพื่อรองรับสัญลักษณ์ในหน้าต่าง Windows CMD
02

Auto Promotion Logic

ตั้งกลไกแยกแยะและคัดลอกข้อมูลเข้าสู่ฐานข้อมูลหลักตามรอบปฏิทินปฏิทิน

  • เดือนคี่ (Odd Month): เขียนข้อมูลบันทึกเข้าเฉพาะโฟลเดอร์ Event ประจำเดือนนั้น ๆ
  • เดือนคู่ (Even Month): ย้อนกลับไปค้นหาและจับคู่เรนเจอร์ของเดือนคี่ก่อนหน้าที่มีทั้งร่างปกติและอัลตร้า
  • KEEP/TEMP Filter: ตรวจเช็คฟิลด์สถานะ (status) คัดลอกเข้า Base Database เฉพาะตัวที่เป็น KEEP เท่านั้น
03

Changelog & Pipeline

ประสานงานแก้ไขระบบจดบันทึกเวอร์ชันและวางสถาปัตยกรรมบนคลาวด์ CI/CD

  • Auto version bump: ปัดเวอร์ชันขึ้น 1 Minor โดยอัตโนมัติ (เช่น 3.0.2 -> 3.1.0 -> 3.2.0)
  • updates.json Logging: ลงเวลาไทย (UTC+7) พร้อมข้อความ "Add new content for [Month]."
  • GitHub Actions Workflow: รัน Scrape แบบไร้หน้าต่าง (Headless) คัดลอกรูปภาพและคัดแยกส่งไป Git ภาพนอก

วิธีตั้งค่าเพื่อเริ่มใช้งานจริง (Production Deployment Checklist)

1

สร้าง GitHub Personal Access Token (PAT)

สร้าง Token ใน GitHub Profile Settings -> Developer Settings -> Personal access tokens (classic) โดยกำหนด Scope สิทธิ์ **`repo`** ให้ครบถ้วน

2

ผูกตัวแปร Secrets ใน Repository หลัก

นำ Token ที่ได้ไปตั้งค่าไว้ใน Repository หลัก (gachame-v3) -> Settings -> Secrets and variables -> Actions โดยตั้งชื่อตัวแปรว่า IMAGE_REPO_PAT

3

เปลี่ยนเป้าหมาย Repository รูปภาพ

ในไฟล์ .github/workflows/auto-update.yml บรรทัดที่ 75 ปรับแก้จาก repository: 'gachame/images' ให้ชี้ไปยังคลังที่เก็บรูปภาพจริงของคุณ

4

ทดสอบการสั่งงาน (Manual Trigger)

ไปที่ Actions tab บน GitHub -> เลือก Auto Update Game Data -> กด **Run workflow** แล้วกรอกเดือน/เลือกประเภททดสอบที่ต้องการเพื่อเริ่มรันงาน
