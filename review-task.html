บันทึกสรุปการพัฒนา Gacha Engine

ได้ทำการพัฒนาโมดูลตัวคำนวณการสุ่มกาชา (Gacha Engine) ในไฟล์ src/engine/gachaEngine.ts ตามขั้นตอนขั้นตอนวิธี (Algorithm) ที่ระบุในเอกสาร docs/probability-engine.md โดยแยกส่วนการทำงานออกจากกันอย่างอิสระและเป็นอิสระจาก React โดยสิ้นเชิง เรียบร้อยแล้ว รายละเอียดมีดังนี้:

1. สถาปัตยกรรมการแยกส่วนของฟังก์ชันการสุ่ม (Decoupled Engine Logic)

  • validateBannerConfig: ทำหน้าที่ตรวจสอบแบนเนอร์กาชาก่อนการสุ่ม (เช่น อัตราสุ่มรวมต้องได้ 100% พอดี, ไอเทมพรีเจอร์ต้องอยู่ในฐานข้อมูล, อัตราสุ่มไอเทมฟีเจอร์ต้องไม่เกินเพดานของความหายากนั้นๆ)
  • generatePoolByRarity: แยกประชากรไอเทมในตู้กาชาออกเป็นกลุ่มย่อยตามระดับความหายาก (Stage 1.1 Pool Generation)
  • selectRarity: สุ่มหาความหายากที่จะได้รับตามสัดส่วนของตู้ (Stage 1 Selection)
  • calculateItemProbabilities: คำนวณความน่าจะเป็นของไอเทมย่อยแบบ Dynamic โดยคิดสัดส่วนไอเทมฟีเจอร์และเฉลี่ยสัดส่วนอัตราที่เหลือให้กับไอเทมปกติเท่าๆ กัน (Remaining Rate Distribution Formula)
  • selectItem: สุ่มเลือกไอเทมปลายทางจากรายการความหายากตามความน่าจะเป็นที่คำนวณไว้ข้างต้น (Stage 2 Selection)
  • rollGacha / rollMultiGacha: ฟังก์ชันประมวลผลกระบวนการสุ่มกาชา 1 ครั้ง หรือการสุ่มพร้อมกันทีละหลายครั้ง

2. สถาปัตยกรรมทางเทคนิค (Technical Details)

  • ไม่มีความเกี่ยวข้องกับ React: ทุกฟังก์ชันเป็น Vanilla TypeScript ที่รับค่าพารามิเตอร์และคืนผลลัพธ์เป็นข้อมูลดิบ สามารถนำไปทดสอบ (Unit Test) หรือนำไปเชื่อมโยงกับ Framework อื่นๆ ได้ง่าย
  • รองรับการทำ Deterministic: ทุกฟังก์ชันสุ่มรองรับการส่งฟังก์ชัน randomFn เข้ามาทดแทน Math.random() เพื่อจำลองค่าการทดสอบที่ควบคุมและทำนายผลลัพธ์ได้อย่างแม่นยำ

3. การทดสอบและการตรวจสอบความถูกต้อง

  • รันคำสั่ง npm run build แล้ว บิลด์โปรเจกต์ผ่านการตรวจสอบอย่างละเอียดของ TypeScript Compiler โดยไม่มีข้อผิดพลาด
